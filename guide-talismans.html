Collection & equipment reference

Talisman Codex.

The Codex is the reference layer for Talisman discovery and ownership. The Talisman Bag is the equipped layer: it determines which owned pieces contribute to the active build. This guide separates those responsibilities so collection progress, acquisition and equipped effects stay understandable.

Server-side behavior verifiedPersistent collection stateSecret requirements remain concealed
01 / State model

Every Codex entry advances through a controlled reveal.

The state machine separates discovering an item from unlocking its acquisition path and finally recording ownership.

State is authoritative on the server.

The interface is a presentation of server-evaluated state. A clicked icon is not trusted as proof that an entry is unlocked or claimable.

02 / Library structure

Different acquisition stories share one Codex model.

Categories organize how an entry is discovered and understood. They do not create separate ownership systems.

Secret means secret.

Pixel Guides documents that concealed Talisman content exists, but it does not publish hidden identities, activation combinations or requirement trees before the game reveals them. Documentation should explain the system without invalidating discovery.

03 / Acquisition

The Codex tracks ownership without becoming every reward source.

An entry's acquisition source is part of its content definition. The interface cannot turn an external or in-world reward into an extra Codex grant.

Duplicate grant paths are deliberately avoided.

Codex claims are only accepted for content configured for that source, and the ownership transition is committed as part of the same server-side operation.

04 / Equipment

Owned is not the same as equipped.

The Codex records collection progress. The Talisman Bag defines the active equipped set that contributes effects to the player's build.

Bag changes are committed on close and the active effect set is recalculated from the resulting equipped contents. Nexus Jewelry shares this equipment surface but uses its reserved Jewelry positions rather than behaving like an unrestricted normal slot.

Rarity is a shared progression language.

The Talisman system uses Pixel's global item rarity ladder instead of maintaining a second category-specific rarity model.

05 / Advanced effects

Effects resolve in a defined order.

The order matters because contextual bonuses and advanced combinations should modify a stable base rather than feed back into themselves.

No recursive stacking loop.

Synergy is evaluated from equipped item identity and remains world-neutral. Meta modifiers resolve after the earlier stages and use the strongest qualifying modifier for the same eligible effect instead of chaining repeatedly.

Advanced combinations are documented by behavior, not by spoiler.

This public guide explains how Synergy and Meta behave, but intentionally does not publish concealed set composition or hidden discovery conditions. Exact player-visible combinations can be documented only where Pixel intends them to be public.

06 / Documentation confidence

Mechanics verified; client presentation still has a separate gate.

Pixel Guides distinguishes source/server confidence from things that can only be proven by actually using the interface inside Minecraft.
