Collection & equipment reference

Talisman Codex.

The Codex tracks Talisman discovery and ownership. The Talisman Bag is the equipped layer: it determines which owned pieces contribute to the active build. This guide separates those responsibilities so collection progress, acquisition and equipped effects stay understandable.

Server-verified mechanicsPersistent collection stateSecret requirements remain concealed
01 / State model

Every Codex entry advances through a controlled reveal.

The four states separate discovering an entry from unlocking its acquisition path and finally recording ownership.

Requirements determine Codex state.

Interacting with an entry does not bypass its discovery or acquisition requirements. The Codex reflects the state the player has actually reached.

02 / Library structure

Different acquisition stories share one Codex model.

Categories organize how an entry is discovered and understood. They do not create separate ownership systems.

Secret means secret.

Pixel Guides documents that concealed Talisman content exists, but it does not publish hidden identities, activation combinations or requirement trees before the game reveals them. Documentation should explain the system without invalidating discovery.

03 / Acquisition

The Codex records ownership without duplicating every reward source.

A Talisman keeps its intended acquisition path whether it comes from world progression, the Codex itself, another progression system or concealed content.

One acquisition should not become two rewards.

When another gameplay source grants a Talisman, the Codex records ownership rather than granting a second copy simply because the collection state changed.

04 / Equipment

Owned is not the same as equipped.

The Codex records collection progress. The Talisman Bag defines the active equipped set that contributes effects to the player's build.

Changes to the equipped set take effect when the Bag closes. Nexus Jewelry shares this equipment surface but uses reserved Jewelry positions rather than behaving like an unrestricted normal slot.

Rarity is a shared progression language.

The Talisman system uses Pixel's global item rarity ladder instead of maintaining a second category-specific rarity model.

05 / Advanced effects

Effects resolve in a defined order.

The order matters because contextual bonuses and advanced combinations modify a stable base instead of feeding back into themselves.

No recursive stacking loop.

Synergy depends on the equipped combination and remains world-neutral. Meta applies after the earlier stages and uses only the strongest qualifying modifier for the same eligible effect rather than repeatedly stacking equivalent modifiers.

Advanced combinations are documented by behavior, not by spoiler.

This public guide explains how Synergy and Meta behave, but intentionally does not publish concealed set composition or hidden discovery conditions. Exact combinations are documented only where Pixel intends them to be public.

06 / Documentation confidence

Mechanics are server verified; presentation has a separate gate.

Mechanics and persistent collection behavior have server-level evidence. Visual, audio and interaction details remain explicitly pending until they are checked in a real Minecraft client.
