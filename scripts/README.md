# PixelWeb Repository Checks

- `security_scan.py` scans committed text files for common secret material without requiring external dependencies.
- `validate_site.py` checks top-level HTML integrity, CSP/transport policy, canonical-data publication guards, ordinary local references and the sitemap/index publication contract. Every indexable page must declare exactly one absolute HTTPS `rel="canonical"` matching its public URL in `sitemap.xml`; duplicate, missing, mismatched or non-sitemap canonicals are rejected. It also rejects insecure absolute HTTP URLs and protocol-relative HTML/CSS resource URLs, and prevents the repository-level `robots.txt` from regressing to a blanket `Disallow: /`; documentation separately records that this robots file is not authoritative on the current `/PixelWeb/` project-site URL.
- `validate_social_metadata.py` validates Open Graph and Twitter metadata for every sitemap-indexed page. It requires unique document titles and meta descriptions across indexed URLs, one coherent social block per page, keeps `og:url` aligned with the canonical URL and sitemap, keeps `og:title` aligned with the document title, keeps `og:description` aligned with the page's single meta description, requires Twitter title/description to mirror Open Graph, and locks the shared social image/alt text to the official Pixel Network logo. Intentionally `noindex` compatibility/error pages remain outside this indexed-page contract.
- `validate_runtime_contracts.py` validates deferred media references (`data-src`, `data-poster`, `data-srcset`), rejects direct `element.style = ...` assignments that would weaken the strict style/CSP model, requires canonical public pages to load the navigation hardening layer, preserves the desktop fine-pointer hover-only Explore/Development/Community contract above the 980 px mobile breakpoint, requires every detailed `guide-*.html` fallback navbar to mark exactly `guides.html` as `aria-current="page"`, rejects any local same-page or cross-page fragment link whose target `id` does not exist in the destination top-level HTML document, and requires the main `guides.html` library to contain exactly one primary `data-guide-entry` for every detailed `guide-*.html` page with no duplicate or orphan entries.
- `validate_accessibility.py` checks baseline document structure: language, viewport, non-empty titles, exactly one `<main>`, descriptions on indexable pages, explicit `alt` attributes on images, valid static `aria-labelledby` / `aria-describedby` / `aria-controls` ID references, non-orphaned `<label for>` targets, accessible naming for visible `input`/`textarea` controls, and explicit valid `scope` semantics plus captions on tables.
- `validate_player_facing_copy.py` rejects known repository-test, database-path, wiring, deployment and implementation-only phrases from browser-public root HTML/JavaScript and public data files while deliberately allowing legitimate evidence labels, formulas, stat keys and player commands.
- `validate_media_integrity.py` verifies the approved Raphael, Azazel, Abyss and Astral PNGs by byte size, 1448×1086 dimensions and exact Git blob SHA. Those four source files must remain byte-identical.
- `validate_public_data.js` loads `data/network.js` and `data/worlds-media.js` in restricted Node VMs and checks canonical-model consistency. It validates current World count/order, summed mines, World encounter count, Nexus encounter/boss/difficulty counts, Nexus access invariants, partial Skyblock boundaries, Store publication state and local landing-page targets. Skyblock partial-feature copy is constrained to player-facing `Partial` / `Planned` states and must not expose source, wiring, command, manager, database or class-level implementation detail. Security-sensitive public destinations are not accepted merely because they use HTTPS: Discord, Store and legacy GitBook routes must remain the approved canonical destinations. Worlds media keys must match the four canonical World ids; landscape images must use the approved Pixel GitBook proxy, expected GitBook storage host and Pixel Network's specific GitBook upload space, while boss artwork must remain an existing local `assets/worlds` resource. This validator checks relationships and publication policy; it is not a second gameplay rendering-data source.
- `build_public_site.py` stages `_site/` from explicit publication roots: sitemap pages plus the `noindex` legacy Forum redirect and 404 page, statically referenced root resources, recursively resolved local CSS `url(...)` / quoted `@import` dependencies, the declared Play-modal runtime stylesheet, and the intentionally browser-public `assets/` and `data/` trees. Arbitrary root `.html`, `.css` or `.js` files are not copied merely because of their extension. Source symlinks and protocol-relative HTML/CSS references are rejected rather than dereferenced or silently accepted into the artifact.
- `validate_public_bundle.py` verifies that `_site/` contains only declared public HTML, referenced/approved root resources and expected static asset/data formats. It re-validates local HTML/deferred-media/CSS dependencies, rejects symlinks without dereferencing them, rejects protocol-relative references, and rejects internal repository paths, environment files, key/certificate material, logs/databases, root-relative project-site URLs and missing local references.

All checks are dependency-free and are executed by `.github/workflows/quality-gate.yml` together with `node --check` for repository JavaScript. The gate builds and validates `_site/` but does **not** currently switch the live GitHub Pages source to that artifact while the account-level Actions billing/startup block remains unresolved.

Manual workflow dispatch requires an explicit branch, tag or commit SHA. This lets the workflow definition installed on `main` validate the actual candidate ref rather than accidentally validating a different tree.

A red GitHub Actions badge is not interpreted as a validator failure unless the runner actually starts and the relevant step executes. The current account-level startup condition prevents that execution and is tracked separately from code quality.
