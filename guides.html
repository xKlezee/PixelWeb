Documentation contract

Verification states exactly what was proved.

Evidence level and feature state are separate. A green build cannot silently become a live-runtime claim, and source presence cannot silently become player availability.

Evidence

Source / server / live-client

Labels identify whether a claim comes from authoritative source and tests, observed server runtime, or a real player-client validation.

State

Current / partial / staged

Completion is tracked independently from evidence. A source-verified subsystem can still be partial when a required player-facing route is unfinished.

Reference

Orientation / current public data

Reference labels identify navigational or canonical-public-data material without upgrading it to a stronger source/server/live-client evidence claim.

Unknown

No evidence means no value

If the available evidence cannot establish a mechanic, requirement or number, the guide leaves it unpublished instead of guessing.

One fact, one source.

A requirement, unlock, reward, stat or mechanic gets one canonical data owner. Other pages may explain the concept, but they do not maintain independent copies of the same value.
